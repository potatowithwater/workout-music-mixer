# 运动节拍音乐混音器 Workout Music Mixer

把你本地的 MP3 曲库，合成**一首节奏统一、节拍严丝合缝、响度一致**的连续运动音乐。

适合爬坡、椭圆机、跑步、动感单车等需要**稳定步频**的场景：选一首和你当前步调最合拍的歌当基准，工具自动把其他歌变速到同一 BPM，再按节拍网格把它们首尾衔接起来，全程无需手动对轨。

---

## 它能做什么

- **自动 BPM 分析**：批量扫描文件夹内所有 MP3，用 `librosa` 检测每首歌的 BPM 和每一个节拍的精确时间点
- **基准歌驱动**：你选一首最合步频的歌，其余歌曲全部向它的 BPM 靠拢
- **变速不变调**：把每首歌伸缩到目标 BPM，音高不变
- **节拍级无缝衔接**：后一首的第一拍，精确落在前一首最后一拍之后**正好一拍**，交叉淡化覆盖完整的一拍
- **响度归一化**：按 ITU-R BS.1770（LUFS）标准逐首对齐 + 整体收敛，衔接处不会忽大忽小
- **软限幅**：真峰值严格控制在 -1.0 dBTP 以内，响而不炸
- **立体声保真**：优先使用支持多声道的变速引擎，不做无谓的单声道混缩

## 快速开始

### 1. 安装依赖

```bash
pip install numpy librosa soundfile imageio-ffmpeg pyloudnorm
```

`imageio-ffmpeg` 自带一份真正的 ffmpeg 静态二进制，装了它就不用自己配 PATH，跨平台最省事。

### 2. 运行

```bash
python workout_music_mixer.py
```

### 3. 按提示操作

```
请输入 MP3 文件夹路径: /Users/me/Music
```

脚本会扫描并列出所有歌曲的 BPM：

```
分析结果：
  [0] Song A.mp3   120.3 BPM  (214 秒)
  [1] Song B.mp3   128.1 BPM  (198 秒)
  [2] Song C.mp3   139.7 BPM  (226 秒)
```

接着依次选：

| 步骤 | 提示 | 说明 |
| --- | --- | --- |
| ① 基准歌 | `选择与你步频最一致的基准歌曲序号` | 输入序号，其余歌曲向它靠拢 |
| ② 匹配模式 | `1=自动（±15%） 2=手动` | 自动模式会筛出 BPM 接近的歌；手动可多选，如 `0,2,5` |
| ③ 响度档位 | `1) -16 / 2) -13 / 3) -11 / 4) -9` | 默认第 3 档（见下表） |
| ④ 码率 | `[320k]` | 可选 192k / 256k / 320k |

输出文件保存在**你的 MP3 文件夹**里，命名如 `workout_mix_120BPM.mp3`。若同名文件已存在，会自动加序号避免覆盖。

### 响度档位怎么选

| 档位 | 目标响度 | 适用场景 |
| --- | --- | --- |
| 1 | -16 LUFS | 安静环境，保留最多动态 |
| 2 | -13 LUFS | 接近流媒体标准 |
| 3 | **-11 LUFS（推荐）** | 健身房、椭圆机 |
| 4 | -9 LUFS | 户外跑步、环境嘈杂 |

> 提示：档位越高越响，但动态压缩也越狠，鼓点的冲击力会被压平。一般选 `-11` 最平衡。

## 变速引擎：四档自动降级

脚本启动时会自动探测并打印当前使用的引擎，**无需手动配置**：

```
变速引擎: ffmpeg atempo（良好，立体声，无金属味）
```

| 优先级 | 引擎 | 音质 | 声道 | 获取方式 |
| --- | --- | --- | --- | --- |
| ① | rubberband 命令行 | 最佳 | 立体声 | `brew install rubberband && pip install pyrubberband` |
| ② | ffmpeg rubberband 滤镜 | 佳 | 立体声 | 部分 ffmpeg 构建自带 |
| ③ | ffmpeg atempo | 良好 | 立体声 | 装了 ffmpeg 即自动可用 |
| ④ | librosa 相位声码器 | 一般 | 单声道 | 内置兜底 |

**为什么 atempo 比 librosa 好**：atempo 用的是时间域 WSOLA 算法，不会产生相位声码器那种"金属味 / 水下声"，且完整保留立体声。对运动场景来说，③ 已经足够好。

想要 ① 那一档（macOS）：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install rubberband
pip install pyrubberband
```

装完直接重跑脚本，横幅会变成 `rubberband 命令行（最佳，立体声）`，代码不用改。

## 实现原理

```
MP3 曲库
   │
   ├─① 分析：librosa.beat.beat_track → BPM + 每个节拍的时间戳
   │
   ├─② 选基准：用户指定的那首歌的 BPM 作为 target_bpm
   │
   ├─③ 变速：rate = target_bpm / 原BPM，变速不变调
   │         节拍时间同步缩放：new_beats = beats / rate
   │
   ├─④ 裁剪：以第一拍为起点，结尾留 2 拍尾巴
   │
   ├─⑤ 逐首响度对齐：每首独立归一化到目标 LUFS
   │
   ├─⑥ 排版：starts[i] = starts[i-1] + 前一首最后一拍 + 一拍间隔
   │         → 相邻两首的节拍网格严格连续
   │
   ├─⑦ 合成：铺进总轨，重叠的一拍内交叉淡化
   │
   └─⑧ 母带：整体归一化 → 软限幅（-1.0 dBTP）→ 导出 MP3
```

### 节拍对齐的关键

光有相同 BPM 是不够的——两首歌的**节拍相位**必须对齐，否则衔接处会听出明显的"错位感"。

本工具的做法是：先算出每首歌的**全局起始时间**，让

```
后一首第一拍的时刻 = 前一首最后一拍的时刻 + 一个完整拍子的时长
```

这样整条音轨的节拍网格从第一秒到最后一秒都是连续的，跑起来每一步都踩在拍子上。

## 常见问题

### 提示"未找到真正的 ffmpeg"

PyPI 上有个叫 `ffmpeg` 的包（版本号 1.4），**它不是真正的转码器**，只是个命令行参数封装库，装了没用。

```bash
pip uninstall ffmpeg -y
pip install imageio-ffmpeg
```

脚本会验证 `ffmpeg -version` 的真实输出，空壳包会被自动识破并跳过。

### 提示"变速超出安全范围"，某首歌被跳过

变速比限制在 **0.8 ~ 1.25** 之间（即 BPM 差异不超过 ±25%）。超出范围的歌会被跳过，避免严重音质劣化。自动匹配模式默认只筛 ±15%，基本不会触发。

### 某首歌 BPM 识别明显不对

librosa 会做倍频修正（把 <80 的翻倍、>190 的减半），但对极少数复杂编曲仍可能判错。可以改用手动模式（选 `2`）自己挑歌。

### 成品没有 MP3，只有 WAV

说明没找到可用的 ffmpeg。参考上面的解决办法。WAV 本身可以直接播放，只是体积大。

### Windows / Linux 能用吗

能。依赖安装：

```bash
# Windows
pip install imageio-ffmpeg     # 自带二进制，最省事
# 或下载 ffmpeg 加进 PATH

# Linux
sudo apt install ffmpeg
```

## 已知限制

- 变速比超过 ±25% 的歌曲会被跳过（保护音质）
- 每首歌只取从第一拍到最后一拍的片段，开头的前奏静音会被裁掉
- 不做调性（key）匹配，衔接处偶尔会有和声上的跳变
- 单声道源文件无法变成立体声，只能保持单声道
